# ADR 0003 — 키워드·벡터 결과를 앱에서 합치는 방법 (RRF)

- **상태:** Accepted
- **날짜:** 2026-07-20
- **관련:** ADR 0007 (벡터 엔진 선택)

## 배경 (무엇을 정해야 하나)

검색은 두 엔진을 동시에 써요.

- **키워드 검색(ES, BM25)** — 글자가 얼마나 맞나로 점수를 매겨요.
- **벡터 검색(Qdrant)** — 뜻이 얼마나 비슷한가로 점수를 매겨요.

각자 "장소 목록 + 점수"를 돌려주는데, 문제는 **두 점수의 단위가 완전히 달라요.** BM25 점수는
몇 점, 몇십 점까지도 나오고, 벡터 유사도는 0~1 사이예요. 이 둘을 그냥 더하면 숫자가 큰 쪽
(보통 BM25)이 결과를 독식해요. **그럼 어떻게 공평하게 합칠까?**

## 결정

**애플리케이션 레이어에서 RRF(Reciprocal Rank Fusion)로 직접 합친다.**

RRF는 점수가 아니라 **순위**만 써요. 각 결과의 순위로 `1 / (k + 순위)` 점수를 매겨서 더해요.
점수 단위가 달라도 순위는 공평하니까, 한쪽이 독식하지 않아요.

```kotlin
fun rrf(rankings: List<List<String>>, k: Int = 60): List<Pair<String, Double>> {
    val scores = HashMap<String, Double>()
    for (ranking in rankings) {
        ranking.forEachIndexed { i, id -> scores.merge(id, 1.0 / (k + i + 1), Double::plus) }
    }
    return scores.entries.sortedByDescending { it.value }.map { it.key to it.value }
}
```

## 왜 (근거)

- **점수 스케일 문제를 우회해요.** 순위만 쓰니 BM25와 벡터 점수를 억지로 같은 잣대로 맞출 필요가 없어요.
- **엔진 내장 기능 대신 앱단인 이유** — 검색 엔진에도 RRF 기능이 있지만 상위 라이선스(유료) 제약이
  있어요. 그리고 우리 결과는 애초에 **서로 다른 시스템(ES + Qdrant)** 에서 와요. 그래서 앱단에서
  직접 합치는 게 라이선스 제약도 피하고, 두 엔진을 자유롭게 조합할 수 있어요.

## 언제였다면 다른 선택을 했을까

**단일 엔진(ES만)** 을 쓰고 라이선스가 허용된다면, 엔진 내장 결합 기능을 쓰는 게 더 단순해요.
이 프로젝트는 별도 벡터 엔진(Qdrant)까지 조합하는 하이브리드라, 앱단 결합이 자연스러워요.

## 결과 (이렇게 하면 뒤따르는 일)

- 각 엔진은 "순위 목록"만 돌려주면 돼요. 결합은 앱이 책임져요.
- `k` 값(기본 60)으로 순위의 영향력을 조절할 수 있어요. 튜닝 대상이에요.
- 결합 로직은 순수 함수라 **단위 테스트하기 쉬워요** — 다양한 순위 조합을 검증해둬요.
