# ADR 0004 — 쿠키리스 세션 모델을 선택

- **상태:** Accepted
- **날짜:** 2026-07-20

## 배경

추천을 하려면 "이 사용자가 지금 세션에서 무엇을 봤는가" 하는 흐름이 필요합니다. 이를 위해
사용자를 **어떻게 식별할지** 정해야 합니다. 방법은 두 가지입니다.

- **(A) 쿠키 + 영구 식별** — 쿠키를 심어 재방문까지 같은 사용자로 추적하고, 취향을 계속 누적합니다.
- **(B) 쿠키리스** — 브라우저 임시 저장소(sessionStorage)에 UUID 하나만 둡니다. 세션이 끝나면 사라지고, 재방문은 식별하지 않습니다.

## 결정

**(B) 쿠키리스를 택합니다.** 임시 UUID로 "현재 세션 안의 행동"만 보고, 재방문 추적은 하지 않습니다.

## 근거

- **추천에 필요한 것은 '현재 세션의 흐름'으로 충분합니다.** 직전에 무엇을 봤는지만 알면 다음에
  선호할 만한 것을 고를 수 있습니다. 재방문마다 사용자를 영구 식별할 필요는 없습니다.
- **재방문을 추적하지 않으면 따라오는 이점이 있습니다.** 쿠키 동의 배너가 필요 없고,
  개인정보를 최소한만 다루게 됩니다. "필요한 만큼만 수집한다"는 프라이버시 원칙을 구조로 지키는 것입니다.
- 이 행동 데이터는 순간순간 바뀌므로 **빠른 차선(Redis 실시간)** 에서 다룹니다.
  (느리게 바뀌는 콘텐츠는 증분 색인이라는 '천천히 차선'으로 — ADR 0001과 짝을 이룹니다.)

## 다른 선택이 유효한 조건

**개인화가 핵심 가치**인 서비스, 즉 방문할수록 취향이 누적되어 정교해지는 것이 중요한 서비스라면
(A) 영구 식별이 필요합니다. 이 서비스의 목적은 "현재의 탐색을 더 좋게" 만드는 것이므로 세션 범위로 충분합니다.

## 결과

- 세션 UUID를 발급하고, 일정 시간 뒤 만료(TTL)시킵니다.
- 세션의 행동 순서는 Redis에 짧게 저장합니다(만료 포함).
- 개인 식별 정보를 저장하지 않으므로, 데이터 관리 부담과 프라이버시 리스크가 줄어듭니다.
