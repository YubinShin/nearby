# ADR 0004 — 쿠키 없이 세션 다루기 (프라이버시)

- **상태:** Accepted
- **날짜:** 2026-07-20

## 배경 (무엇을 정해야 하나)

추천을 하려면 "이 사용자가 지금 세션에서 뭘 봤나" 하는 흐름이 필요해요. 그럼 사용자를
**어떻게 식별할까?** 두 가지 방법이 있어요.

- **(A) 쿠키 + 영구 식별** — 쿠키를 심어서 재방문까지 같은 사람으로 추적. 취향을 계속 누적.
- **(B) 쿠키리스** — 브라우저 임시 저장소(sessionStorage)에 UUID 하나만. 세션 끝나면 사라지고, 재방문은 식별하지 않음.

## 결정

**(B) 쿠키리스를 택한다.** 임시 UUID로 "지금 이 세션 안의 행동"만 보고, 재방문 추적은 하지 않는다.

## 왜 (근거)

- **추천에 필요한 건 '지금 세션의 흐름'이면 충분해요.** 방금 무엇들을 봤는지만 알면 다음에 좋아할
  만한 걸 고를 수 있어요. 재방문마다 누가 누군지 영구히 알 필요는 없어요.
- **재방문을 추적 안 하면 좋은 게 따라와요.** 쿠키 동의 배너 같은 것도 필요 없고,
  개인정보를 최소한만 다루게 돼요. "필요한 만큼만 수집한다"는 프라이버시 원칙을 구조로 지키는 거예요.
- 이 행동 데이터는 순간순간 바뀌니 **빠른 차선(Redis 실시간)** 에서 다뤄요.
  (느리게 바뀌는 콘텐츠는 증분 색인이라는 '천천히 차선'으로 — ADR 0001과 짝이에요.)

## 언제였다면 다른 선택을 했을까

**개인화가 핵심 가치**인 서비스, 즉 방문할수록 내 취향이 쌓여서 점점 정교해지는 게 중요하다면
(A) 영구 식별이 필요해요. 이 서비스는 "지금의 탐색을 더 좋게" 만드는 게 목적이라, 세션 범위면 충분해요.

## 결과 (이렇게 하면 뒤따르는 일)

- 세션 UUID를 발급하고, 일정 시간 뒤 만료(TTL)시켜요.
- 세션의 행동 순서는 Redis에 짧게 저장해요(만료 포함).
- 개인 식별 정보를 저장하지 않으니, 데이터 관리 부담과 프라이버시 리스크가 줄어요.
