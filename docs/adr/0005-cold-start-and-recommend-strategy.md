# ADR 0005 — 처음 온 사람에게 뭘 보여줄까 (콜드스타트)

- **상태:** Accepted
- **날짜:** 2026-07-20
- **관련:** ADR 0004 (쿠키리스 세션)

## 배경 (무엇을 정해야 하나)

추천은 보통 "과거 행동"을 보고 해요. 그런데 방금 막 들어온 사람은 **행동 데이터가 하나도 없어요.**
이걸 **콜드스타트(cold start)** 문제라고 해요. 이 사람에게 첫 화면에 뭘 보여줄까요?

빈 화면을 보여줄 순 없고, 아무거나(랜덤) 보여주면 품질이 나빠요.

## 결정

**콜드스타트에는 '인기 있고 + 가까운' 장소를, Redis에서 빠르게 보여준다.**
그리고 세션이 쌓이기 시작하면 점점 세션 기반 추천으로 넘어간다.

## 왜 (근거)

행동 데이터가 없어도, **누구에게나 통하는 두 가지 신호**는 있어요.

- **인기** — 많은 사람이 좋아하는 곳(집단의 신호). 첫 방문자에게도 대체로 안전한 선택이에요.
- **거리** — 지금 어디 있는지(위치 신호). 로컬 서비스라 가까운 곳이 특히 중요해요.

이 둘을 합치면 행동 정보가 0이어도 첫 화면부터 그럴듯한 결과가 나와요. 인기 순위는 미리 계산해
**Redis에 캐시**해두면 즉시 응답할 수 있고요. 그러다 사용자가 몇 개 둘러보면, 그때부터는
세션 흐름(방금 본 것들)과 비슷한 장소로 추천을 **점점 전환**해요.

## 언제였다면 다른 선택을 했을까

**로그인 기반 서비스**라서 가입할 때 취향을 미리 받는다면, 콜드스타트가 훨씬 약해져요.
그런데 이 서비스는 쿠키리스(ADR 0004)라 첫 방문 정보가 없어요. 그래서 '인기 + 거리'가 가장 현실적인 출발점이에요.

## 결과 (이렇게 하면 뒤따르는 일)

- 인기 순위를 주기적으로 집계해 Redis에 캐시해둬요.
- 거리 계산은 원천(PostGIS)의 지리 기능으로 해요.
- 세션이 진행될수록 '인기+거리 → 세션 기반'으로 넘어가는 단계별 fallback을 둬요.
  (추천이 실패하거나 데이터가 부족할 때 안전하게 기댈 기본값 역할도 겸해요.)
