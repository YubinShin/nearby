# ADR 0005 — 콜드스타트 추천을 인기·거리 기반으로 구성

- **상태:** Accepted (예정)
- **날짜:** 2026-07-20
- **관련:** ADR 0004 (쿠키리스 세션)

## Context

추천은 보통 과거 행동을 근거로 합니다. 그러나 처음 진입한 사용자는 행동 데이터가 전혀 없습니다. 이를 **콜드스타트(cold start)** 문제라 합니다. 이 사용자의 첫 화면에 무엇을 보여줄지 정해야 합니다.

빈 화면은 선택지가 아니고, 무작위 노출은 품질이 나쁩니다.

## Decision

콜드스타트에는 '인기 있고 + 가까운' 장소를 Redis에서 즉시 제공합니다. 세션 행동이 쌓이기 시작하면 점진적으로 세션 기반 추천으로 전환합니다.

## Rationale

행동 데이터가 없어도 **누구에게나 유효한 두 가지 신호**가 있습니다.

- **인기** — 다수가 선호하는 장소(집단 신호).
- **거리** — 현재 위치(위치 신호). 로컬 서비스 특성상 근접성의 비중이 특히 큽니다.

인기 순위는 미리 집계해 Redis에 캐시해 두면 즉시 응답합니다. 사용자가 몇 개를 둘러본 뒤에는 세션 흐름(직전에 본 장소들)과 유사한 장소로 추천을 **점진 전환**합니다.

## Revisit conditions

**로그인 기반 서비스**라서 가입 시점에 취향 정보를 미리 받는다면 콜드스타트 문제 자체가 크게 약해집니다. 이 서비스는 쿠키리스(ADR 0004)라 첫 방문 시점의 정보가 없으므로, '인기 + 거리'가 가장 현실적인 출발점입니다.

## Consequences

- 인기 순위를 주기적으로 집계해 Redis에 캐시해 둡니다.
- 거리 계산은 원천(PostGIS)의 지리 기능을 사용합니다.
- 세션이 진행될수록 '인기+거리 → 세션 기반'으로 넘어가는 단계별 fallback을 둡니다. (추천이 실패하거나 데이터가 부족할 때 안전하게 기댈 기본값 역할도 겸합니다.)
