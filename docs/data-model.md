# Data Model

이 문서는 장소의 **원본**이 저장되는 원천 창고(PostGIS)의 구조를 정리합니다. 검색 엔진(ES·Qdrant)에 들어가는 색인용 데이터가 아닙니다. (색인은 여기서 파생됩니다 — ADR 0001 "원천은 한 곳, 검색용 사본은 바뀔 때만".)

## Data sources

- **소상공인시장진흥공단_상가(상권)정보** (공공데이터포털, 최신 `20260331`). 전국 영업 중 상가업소 정보. 원자료는 국세청·카드사 기반.
- 형식: CSV · UTF-8 · 콤마 구분. 지역별로 나뉘어 제공 → **특정 지역(예: 강남구)만** 받아 적재.

## Modeling principle

원천은 **원본을 최대한 보존**합니다. 다만 검색 플랫폼이 실제로 쓰는 필드를 명확히 두고, PostGIS의 **공간(geometry) 컬럼**을 더해 거리 계산이 가능하게 합니다.

CSV의 경도·위도(문자열)를 그대로 두지 않고, `geometry(Point, 4326)`로 만들어 공간 인덱스(GiST)를 적용합니다. 그래야 "내 위치에서 반경 1km" 같은 질의가 빠릅니다.

## Table `place`

| 컬럼 | 타입 | 출처(CSV) | 설명 |
|---|---|---|---|
| `place_id` | `text` PK | 상가업소번호 | 원본 고유 키 (멱등 색인의 기준 — ADR 0001) |
| `name` | `text` | 상호명 | 검색 대상 1순위 |
| `branch` | `text` | 지점명 | "스타벅스 강남점"의 "강남점" |
| `category_large` | `text` | 상권업종대분류명 | 예: 음식 |
| `category_mid` | `text` | 상권업종중분류명 | 예: 카페/디저트 |
| `category_small` | `text` | 상권업종소분류명 | 예: 브런치카페 |
| `sido` | `text` | 시도명 | 서울특별시 |
| `sigungu` | `text` | 시군구명 | 강남구 |
| `dong` | `text` | 행정동명 | 역삼동 |
| `jibun_address` | `text` | 지번주소 | |
| `road_address` | `text` | 도로명주소 | 검색·표시용 주소 |
| `lon` | `double precision` | 경도 | 원본 보존 |
| `lat` | `double precision` | 위도 | 원본 보존 |
| `geom` | `geometry(Point, 4326)` | (lon, lat)로 생성 | 거리·반경 질의용 |
| `updated_at` | `timestamptz` | 마지막 변경 시각 (트리거가 갱신) | 증분 색인 워터마크 |
| `deleted_at` | `timestamptz` | 소프트 삭제 표시 | 값이 있으면 증분이 ES 문서를 지움 |

> 나머지 원본 컬럼(우편번호·건물관리번호·표준산업분류 등)은 지금 검색·추천에 쓰지 않습니다. 필요해지면 추가합니다. 원천이므로 **버리기보다 안 넣는 쪽**으로 시작합니다.

## DDL

실제 스키마는 `deploy/postgis/schema.sql`. 핵심은 **`geom`을 경위도에서 자동 생성**하는 것:

```sql
geom geometry(Point, 4326)
  GENERATED ALWAYS AS (ST_SetSRID(ST_MakePoint(lon, lat), 4326)) STORED
```

이렇게 하면 CSV의 lon/lat만 COPY해도 `geom`이 자동으로 채워집니다(별도 UPDATE 없음). `place_geom_gix`(GiST)로 반경·거리 질의를 가속하고, `place_updated_at_idx`는 3단계 증분 색인용.

> **주의(tiger 충돌):** `postgis/postgis` 이미지에는 tiger geocoder 확장이 있고 거기에도 `place` 테이블이 있습니다. 그래서 스키마를 **`public.place`로 명시**해 이름 충돌을 피합니다.

## Loading

`scripts/load_place.sh` 한 번으로: 서울 CSV → 강남구 추출(`scripts/extract_gangnam.py`) → 스키마 적용 → `\copy`. 실측: **강남구 64,239건, 좌표 누락 0건** 적재 확인. 공간 질의(강남역 반경 300m 카페 거리순)도 정상 동작.

> 업종 분류 참고: 카페는 `음식 > 비알코올 > 카페`(소분류)에 있습니다. 필터 시 `category_small` 기준.

## Data limitations

### Missing brand names

`스타벅스`로 검색하면 **0건**입니다. 두 번째 원천(인허가)과 좌표로 맞춰 확인한 결과, 매장은 있습니다. 상호명에서 브랜드가 빠지고 지점명만 남아 있습니다.

| 인허가 (사업장명) | 상가정보 (상호명) | 업종 | 거리 |
|---|---|---|---|
| 스타벅스 신사역점 | `신사역` | 카페 | 9m |
| 스타벅스포스코점 | `포스코` | 카페 | 2m |
| 스타벅스학여울역점 | `학여울역` | 카페 | 5m |
| 스타벅스 청담역6번출구점 | `청담역6번출구` | 카페 | 10m |

- 인허가의 스타벅스 100건 중 **87건**이 반경 30m 안에 카페 업종 상가정보 행과 짝을 이룹니다.
- 두 원천을 이었을 때 "상가정보 쪽에서 앞말이 사라진" 경우가 **377건**인데, 그중 **스타벅스 계열이 83건으로 최다**입니다. 나머지는 대부분 `주식회사`·`(주)` 같은 법인격 표기라 정상적인 차이입니다.

행을 새로 붙일 것이 아니라, **기존 행의 브랜드명을 복원**하면 됩니다. 위치로 두 원천을 이으면 인허가 쪽 이름에서 가져올 수 있습니다.

> **주의:** 아직 못 밝힌 것 — `유니클로` 0건, `다이소` 3건, `무신사` 2건도 같은 이유인지는 모릅니다. 인허가 데이터가 **음식점 계열만** 담고 있어 대조할 상대가 없습니다.

원본 CSV 서울 전체에서도 같습니다 — 상호명에 브랜드가 든 스타벅스 매장 행이 없습니다. 반면 가맹 위주 브랜드는 이름 그대로 들어 있습니다 (강남구 기준): 이디야·투썸·메가커피 등 **144**, 올리브영 **52**, 맥도날드·버거킹·롯데리아 **47**.

### Other limitations

- **시점 고정** — 2026-03 스냅샷입니다. 폐업·신규가 반영되지 않습니다.
- **평점·리뷰·인기도 부재** — 랭킹 근거를 질의 로그에서 직접 만들어야 합니다 (아키텍처 리뷰 #11).
- **로컬 범위는 강남구**입니다. 서울 전체는 53.7만 건이라 확장 여지로만 남겼습니다.

## Second source (`place_localdata`)

상가정보에서 `스타벅스`가 0건인 원인을 밝히려고 원천을 하나 더 추가했습니다. 결과적으로 **누락이 아니라 상호명에서 브랜드가 빠진 것**이었습니다(위 절 참고).

| 항목 | 상가정보 (`place`) | 인허가 (`place_localdata`) |
|---|---|---|
| 출처 | 소상공인시장진흥공단 상가정보 | 행안부 지방행정 인허가 (휴게음식점) |
| 기준 | 사업자·점포 등록 | **점포별 영업신고** |
| 강남구 건수 | 64,239 (전 업종) | **3,934** (음식점 계열, 영업 중) |
| **스타벅스** | **0** (이름에서 브랜드 탈락) | **100** |
| 업종 분류 | 대/중/소 3단계 | 1단계 (커피숍·편의점·다방…) |
| 폐업 | 없음 (정제됨) | 원본에 **77.1%** 섞여 있음 → 제거 |
| 좌표 | WGS84 | **EPSG:5174** → 변환 필요 |
| 동 | **행정동** (역삼1동) | **법정동**만 (역삼동) → 공간 조인으로 부여 |
| 갱신 | 분기 스냅샷 | **매일** |

교체가 아니라 보완입니다. 커버리지는 인허가가, 분류 체계와 정제도는 상가정보가 낫습니다. 아직 합치지 않고 테이블을 나눠 둡니다 — 통합 스키마(원천 표시·중복 제거)를 정하기 전에 섞으면 어느 행이 어디서 왔는지 잃습니다.

### CRS validation (EPSG:5174)

5174/5181 은 서울에서 300m 차이라 표본으로는 못 가립니다. 3,881건 전수를 두 좌표계로 각각 변환해 경계에 대조했습니다.

| SRID | 경계 밖 | 강남구 밖 | 법정동 일치율 |
|---|---|---|---|
| **5174** | **0** | **1** | **90.93%** |
| 5181 | 7 | 347 | 62.82% |

강남구 밖으로 떨어진 1건은 변환 오류가 아니라 원본 오류입니다 — 강남구 데이터셋에 강북구 주소 행이 섞여 있습니다.

## Administrative boundaries (`adm_dong`)

원천마다 '동'의 종류가 다릅니다. 상가정보는 **행정동**(역삼1동), 인허가는 **법정동**(역삼동). 강남구 기준 법정동 14개가 행정동 22개로 갈라져, 이름만으로는 사실상 맞출 수 없습니다. 가릴 수 있는 정보는 위치뿐이라 좌표를 경계에 떨어뜨려(`ST_Contains`) 판정합니다.

- 원본: [vuski/admdongkor](https://github.com/vuski/admdongkor) — 전국 3,558개, GeoJSON, WGS84
- 적재: 서울 427개 (강남구 22개). 잘못된 경계 0건
- 적재된 22개 동명이 `place.dong`의 22개와 일치했습니다

### Administrative dong validation

상가정보가 준 `dong` 값을 좌표로 재계산해 대조한 결과:

| 항목 | 값 |
|---|---|
| 전체 | 64,239 |
| **일치** | **64,046 (99.70%)** |
| 경계 밖 | 0 |

불일치 193건 중 **161건이 한 건물**(`대치동 937` = 롯데백화점 강남점, 입점 매장들이 한 좌표를 공유)이라, 실질 불일치 지점은 33곳입니다. 전부 행정동 경계에 붙어 있습니다. 어느 쪽이 옳은지는 지번 단위 권위 자료가 없어 단정하지 못합니다.

## Brand name restoration (`place_brand`)

상가정보에서 사라진 브랜드를 인허가 데이터에서 복원합니다.

```
규칙:  인허가 사업장명 = [브랜드] + 상가정보 상호명 + ("점")
예)   '스타벅스 신사역점'  =  '스타벅스' + '신사역' + '점'      (두 좌표 거리 9m)
```

규칙만 쓰면 우연히 앞말이 붙은 잡음이 섞입니다. 두 가지로 거릅니다.

1. **법인격 표기 제외** — `(주)`·`주식회사`는 브랜드가 아닙니다.
2. **같은 브랜드가 5번 이상 나와야 인정.** 진짜 브랜드는 매장마다 반복되고, 우연은 한 번만 나옵니다. 실측 분포가 그대로 보여줍니다:

   | 후보 | 건수 | 판단 |
   |---|---|---|
   | 스타벅스 | 71 | 매장마다 반복 |
   | 스타벅스커피 | 14 | 같은 브랜드의 변형 |
   | 크레스타운 · 백남옥손만두 · 보드게임카페 … | 각 1 | 우연 |

   **빈도 자체가 신뢰도 신호**라, 사람이 브랜드 목록을 관리하지 않아도 됩니다.

`스타벅스커피` 같은 긴 변형은 짧고 빈번한 쪽으로 모읍니다 — 안 그러면 색인에 둘이 따로 들어가 한쪽만 검색됩니다.

**결과: 86건 복원(전부 스타벅스), 매칭 거리 0~26m.**

`place`에 컬럼을 붙이지 않고 테이블을 나눈 이유는, 이것이 **원천이 준 값이 아니라 추론한 값**이기 때문입니다. 섞으면 받은 것과 만든 것의 경계가 사라집니다. 따로 두면 통째로 지우고 다시 만들 수 있고, 색인은 `left join` 하나만 바뀝니다.

> **주의(한계):** 브랜드만 바뀌면 `place.updated_at`이 갱신되지 않아 증분 색인이 감지하지 못합니다. 지금은 전체 재색인으로만 반영됩니다 (아키텍처 리뷰 #20).

## Design decisions

- **`place_id`를 원본 상가업소번호로.** 같은 데이터가 두 번 들어와도 결과가 같도록(멱등), 색인·업서트의 기준 키를 원본 고유 키로 둡니다 (ADR 0001).
- **`geom`을 따로 둠.** CSV의 경위도는 문자열이라 거리 계산에 쓸 수 없습니다. `geometry(Point, 4326)`으로 변환하고 GiST 인덱스를 적용해야 지리 질의가 빨라집니다. SRID 4326 = 흔한 WGS84 경위도.
- **업종을 대/중/소로 분리.** 필터("카페만")와 색인 가중치에 쓰기 좋게 계층을 살려둡니다.
- **`updated_at`.** 증분 색인이 "언제 이후 바뀐 것"을 골라가는 워터마크입니다. `place_touch_updated_at()` 트리거가 UPDATE 마다 갱신하고 `place_updated_at_idx`로 조회합니다.
