# 아키텍처 — 쉽게 풀어쓴 전체 그림

이 문서는 이 플랫폼이 "데이터가 들어와서 → 검색 결과가 나가기까지" 어떻게 동작하는지를
전문용어를 최대한 풀어서 설명해요. 각 조각이 *무엇이고, 왜 여기 있는지*에 초점을 맞췄어요.

## 한눈에 보기

이 시스템은 크게 세 덩어리예요.

1. **데이터를 모으고 검색 가능하게 만드는 쪽** (수집 → 원천 저장 → 색인)
2. **검색·추천 요청에 답하는 쪽** (공통 API)
3. **이 모든 걸 올려두는 인프라** (Kubernetes)

핵심 아이디어 하나만 기억하면 돼요 — **원천 데이터는 한 곳에 두되, 검색용 사본을 여러 엔진에
"바뀔 때만" 조금씩 만들어 둔다.** 그래야 빠르게 찾고, 낭비 없이 최신 상태를 유지할 수 있어요.

## 등장하는 조각들 (한 줄 설명)

- **PostGIS** — 원천 창고. 장소의 진짜 정보(이름·주소·좌표)가 여기 저장돼요.
  (PostgreSQL에 '위치·거리 계산' 기능을 더한 것)
- **Elasticsearch** — 키워드 검색 엔진. "글자가 얼마나 맞나"로 찾아요. 자동완성도 여기서.
- **Qdrant** — 벡터(뜻) 검색 엔진. 문장을 숫자 묶음으로 바꿔서 "의미가 얼마나 비슷한가"로 찾아요.
- **Redis** — 아주 빠른 임시 저장소. 방금 한 행동, 인기 순위, 비상용 기본 결과를 여기 둬요.
- **`search-api`** — 위 엔진들에 대신 물어보고, 답을 합쳐서 돌려주는 서버.
  여러 서비스가 이 하나만 부르면 되도록 만든 "플랫폼의 입구". **읽기만 해요.**
- **`indexer-batch`** — 원천 창고(PostGIS)에서 읽어 검색 엔진에 밀어넣는 앱. **쓰기만 해요.**
  `search-api` 와 **따로 만들어지고 따로 떠요** (ADR 0011). 이유는 아래에.
- **`search-core`** — 위 두 앱이 **함께 쓰는 규칙**을 담은 라이브러리. 앱이 아니에요.
  브랜드를 정하는 규칙, 문서의 필드 이름, 임베딩 모델이 여기 한 벌만 있어요.

## 데이터가 들어오는 길

공공데이터포털의 **상가정보**(소상공인시장진흥공단)와 **지방행정 인허가 데이터**(행안부)에서 장소 데이터를 받아 **PostGIS에 원천으로** 저장해요.

그다음이 중요한데, 이 원천을 검색 엔진(ES·Qdrant)에 **매번 통째로 다시 넣지 않아요.**
데이터가 **새로 생기거나 바뀌는 '사건(이벤트)'이 있을 때만**, 그 바뀐 부분만 조금씩 반영해요.
이걸 "이벤트 트리거 증분 색인"이라고 부르는데, 쉽게 말하면 *바뀐 것만 골라 업데이트*예요.
왜 실시간으로 안 하냐면 — 아무 변화도 없는데 계속 확인하는 건 낭비라서요.
(자세한 이유는 ADR 0001에 적었어요.)

## 검색 한 번의 여정

사용자가 "분위기 좋은 강남 파스타집"을 검색했다고 해볼게요.

1. 서버가 이 문장을 **키워드 엔진(ES)과 뜻 엔진(Qdrant)에 동시에** 물어봐요.
   - ES는 '강남', '파스타' 같은 단어가 잘 맞는 곳을 순위로 줘요.
   - Qdrant는 '분위기 좋은'처럼 단어로 딱 안 잡히는 느낌까지 의미로 비슷한 곳을 순위로 줘요.
2. 두 순위를 **RRF라는 방법으로 합쳐요.** 점수 스케일이 서로 달라도, *순위*를 기준으로 섞기 때문에
   한쪽이 결과를 독식하지 않고 공평하게 합쳐져요. (자세히는 ADR 0003)
3. 여기에 **거리(PostGIS)** 를 얹어서, 지금 위치에서 가까운 곳 위주로 다듬어요.
4. 최종 목록을 사용자에게 돌려줘요.

두 엔진을 *동시에* 부르는 게 포인트예요. 하나 끝나고 다음을 부르면 느리니까,
서버는 리액티브(WebFlux+코루틴) 방식으로 둘을 나란히 실행해요. (왜 이 방식인지는 ADR 0006)

## 추천은 어떻게

세 가지 상황으로 나눠서 답을 줘요.

- **비슷한 장소** — 지금 보는 곳과 '뜻이 비슷한' 이웃을 Qdrant에서 찾아요.
- **방금 둘러본 흐름** — 사용자가 최근에 본 장소들의 순서를 참고해서 다음에 좋아할 만한 걸 골라요.
- **처음 온 사람** — 아직 아무 정보가 없으니, '인기 있고 + 가까운' 곳을 Redis에서 빠르게 보여줘요.
  (이 '처음 온 사람' 문제를 콜드스타트라고 해요 — ADR 0005)

여기서 한 가지 설계 원칙이 있어요. **콘텐츠(장소 정보)는 느리게 바뀌니 '천천히 차선'(증분 색인)으로,
사용자 행동은 순간순간 바뀌니 '빠른 차선'(Redis 실시간)으로** 나눠서 다뤄요.
성격이 다른 데이터를 같은 속도로 다루지 않는 거예요.

## 세션은 쿠키 없이

누가 무엇을 봤는지 흐름은 필요하지만, **재방문까지 추적하진 않아요.**
브라우저에 임시 UUID 하나만 두고(쿠키 없음), 그 세션 안에서의 행동만 봐요.
이렇게 하면 동의 배너 같은 것도 필요 없고, 프라이버시 원칙도 지킬 수 있어요. (ADR 0004)

## 왜 굳이 여러 조각으로 나눴나 (플랫폼 관점)

"장소 검색 하나"만 만들 거면 이렇게 안 나눠도 돼요. 그런데 목표가 **여러 서비스가 공통으로 쓰는
플랫폼**이라서, 처음부터 이렇게 설계했어요.

- **검색 인덱스를 용도별로 분리** — 본문 검색용과 자동완성용은 요구가 다르니 따로 둬요.
  트래픽이 몰려도 서로 영향을 안 주고, 각각 필요한 만큼만 키울 수 있어요. (ADR 0002)
- **엔진을 역할별로 분리** — 키워드는 ES, 뜻은 Qdrant, 빠른 것은 Redis.
  한 엔진에 다 욱여넣지 않아요.
- **입구를 하나로 통일** — 새 서비스가 검색을 붙이고 싶으면, 엔진들을 몰라도 이 공통 API 하나만
  부르면 돼요. 이게 "플랫폼"이 되는 이유예요.
- **색인기와 검색기를 아예 다른 앱으로** — 아래에 따로 설명할게요.

## 왜 색인기와 검색기를 나눴나 (ADR 0011)

둘은 **성격이 반대**예요.

| | 색인기 | 검색기 |
|---|---|---|
| 언제 힘을 쓰나 | 한 번에 확 (벡터 재색인 8분 12초, 그중 **95.7%가 임베딩 계산**) | 항상 조금씩 (질의 하나에 8ms) |
| 뭐가 중요한가 | 다 끝내는 것 | 빨리 답하는 것 |
| 잠깐 죽으면 | 색인이 밀릴 뿐 | **검색 장애** |
| 동시에 몇 개 | 한 번에 하나 | 수백~수천 요청 |
| 그래서 쓰는 방식 | **Spring Batch + 블로킹** (ADR 0013) | **리액티브** (ADR 0006) |

마지막 행이 핵심이에요. 성격이 반대니까 **쓰는 기술도 반대**예요. 리액티브의 장점은 "기다리는
동안 스레드를 놀리지 않는 것"인데, 색인기는 한 번에 하나만 하니까 아낄 스레드가 없어요.
대신 색인의 병목은 CPU(임베딩 계산이 96%)라 리액티브가 정작 느린 부분을 못 건드려요.

한 프로그램 안에 같이 있으면 **색인기가 메모리를 다 쓰고 쓰러질 때 검색도 같이 죽어요.**
(실무에서 실시간 색인기가 한 달에 최대 14번 그렇게 죽은 적이 있어요.)

전에는 스위치로 "색인 기능을 꺼둔 채로 띄우기"를 했는데, 그건 **같은 집에 커튼 친 것**이었어요.
커튼을 쳐도 집은 하나라 불이 나면 같이 타요. 지금은 아예 **벽**이에요 — 검색기의 실행 파일 안에는
색인 코드가 **들어 있지도 않아요.**

### 나눴더니 새로 생긴 위험, 그리고 대비

한 프로그램일 때는 색인과 검색이 **같은 임베딩 모델을 쓸 수밖에** 없었어요. 같은 코드니까요.
따로 배포하면 이게 어긋날 수 있어요 — 색인기만 새 모델로 바뀌고 검색기는 옛날 것으로 남는 순간이요.

그리고 이 어긋남은 **에러가 안 나요.** 점수는 멀쩡히 계산되는데 그 점수가 의미가 없을 뿐이에요.

그래서 **버전 도장**을 찍어요.

```
색인기: 색인 다 끝내고 → "나는 multilingual-e5-small 로 만들었다" 를 기록
검색기: 뜰 때 그 기록을 읽고 → 내 모델과 다르면 아예 안 뜬다
```

조용히 틀린 결과를 내느니 **시끄럽게 실패하는 쪽**을 골랐어요.

## 인프라

위 엔진들은 Kubernetes 위에 올라가요. 새 버전으로 바꿀 때 서비스가 안 끊기도록,
**별칭(alias)을 새 인덱스로 살짝 바꿔치기하는 방식**으로 무중단 교체를 해요.
(로컬에서 개발할 땐 `docker compose`로 가볍게 띄우고, Kubernetes는 시연할 때만 잠깐 올려요.)
