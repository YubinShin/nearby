# 로드맵 — 무엇을, 어떤 순서로

이 프로젝트의 목표는 **로컬(docker compose)에서 검색 파이프라인이 실제로 끝까지 도는 것**이에요.
데이터 적재 → 색인 → 키워드+벡터 검색 → RRF 결합 → 거리 다듬기까지 *진짜로 동작*하는 걸 목표로 해요.

무엇을 **실제로 만들고**, 무엇을 **설계 문서로만 남기는지**를 분명히 나눠요. 다 만드는 게 목표가
아니라, "이런 걸 설계할 줄 안다"를 **동작하는 핵심 + 확장 설계**로 보여주는 게 목표예요.

## 원칙

- **핵심은 동작, 확장은 설계.** 검색의 뼈대(색인·키워드·벡터·결합)는 실제로 돌리고, 운영 고도화
  (K8s 무중단 배포·멀티클러스터·Kafka 색인·추천 고도화)는 근거 있는 설계 문서로 남겨요.
- **결정마다 ADR.** 왜 그렇게 했는지를 [ADR](adr/)에 남겨요. 이게 이 프로젝트의 알맹이예요.
- **매 단계 빌드/기동 검증.** 문서만 있고 안 도는 상태를 만들지 않아요.

## 설계 문서로만 남기는 범위 (이번엔 구현하지 않음)

실무 경험이 있는 영역이지만, 로컬 데모 범위를 넘어서므로 **구조와 근거만** 남겨요.

- **K8s 무중단 배포** — alias 스왑 기반 인덱스 교체를 K8s에서 운영하는 방식
- **멀티클러스터** — 용도별 클러스터 분리·확장 토폴로지 (ADR 0002의 연장)
- **Kafka 스트리밍 색인** — 증분 색인을 이벤트 스트림으로 (ADR 0001의 연장).
  들어올 자리를 `services/indexer-stream/` 에 **빈 모듈로 만들어 뒀어요** — 이름을 고른 근거와
  채워질 조건은 그 모듈 README 에 있어요 (ADR 0011).
- **추천 고도화** — Item2Item·Sequence·Discovery, Circuit Breaker/Fallback 체인

- ✅ 1단계 완료 (2026-07-22): ES 9.4.2용 KOMORAN 플러그인 재포팅, POS-stop 공격적 stoptags, 커스텀 ES 이미지 실기동 검증, nori 비교 실측 → ADR 0008 반영
- ✅ 2단계 완료 (2026-07-22): 강남구 상가정보 64,239건 PostGIS 적재(geom 자동생성·GiST), 공간질의 검증, `data-model.md`·적재 스크립트 확정. (로컬은 강남구, 서울 전체 53.7만은 확장 여지)
- ✅ 3단계 완료 (2026-07-22): search-api 안에 Kotlin 색인기(R2DBC 스트림 읽기 → ES `_bulk`) 구현. 용도별 인덱스 2개(본문 komoran / 자동완성 edge_ngram) 매핑을 앱 리소스로 소유. 무중단 alias 스왑(전체 재색인 중 검색 90회 무중단 실측), 증분 색인(watermark=인덱스 max updated_at, place_id upsert 멱등) 실측. 타임스탬프 정밀도 버그(PG μs vs ES ms) 발견·수정. 이벤트 드리븐 트리거는 8단계 설계로 이월.
- ✅ 4단계 완료 (2026-07-23): 읽기 경로(`query` 패키지) 신설 — `/v1/search`(cross_fields+AND, 0건 시 70% 완화 폴백, 시군구·행정동·카테고리 필터, 반경 필터·거리순), `/v1/suggest`(결정적 순서), `/v1/instant`(코루틴 팬아웃: 합 7.6ms → 중앙값 3ms). 랭킹은 순수 함수로 분리해 질의 JSON을 단위 테스트로 고정(19개 통과) → ADR 0009. 셀프 크리틱 #5(역할 분리)·#8(관측성)·#10(자동완성 랭킹) 해소, #11~#13 신규 발견.
- ✅ 1단계 재방문 (2026-07-23): 4단계 검색 품질 측정에서 형태소 분석 손실이 드러나 1단계로 되돌아감.
  플러그인에 사용자 사전 로딩 경로(`user_dictionary`/`fw_dictionary`) 추가, 원천 기반 사전 자동 생성기
  (`scripts/build_komoran_dict.py`) 구축. **1단계에서 정한 공격적 `stoptags` 를 실측 근거로 보수적으로
  되돌림** — 상호명 64,239건의 글자 유실 30.81% → 5.57%. 사전은 세 층(자동 추출 1,377 + 사람이 넣는
  시드 `manual.dict` 21 + 검색 로그 채굴 `mine_query_log.py`)으로 구성. 질의 로그(`QueryLog`)를
  확보해 랭킹 튜닝(크리틱 #11)의 선행 조건도 절반 채움. → ADR 0008 갱신
- ✅ 5단계 완료 (2026-07-23): 임베딩 추론을 **앱 안에서**(DJL+ONNX, `multilingual-e5-small` 384차원)
  돌려 색인·질의가 같은 모델을 쓰도록 코드로 강제 → ADR 0010. PostGIS → Qdrant 벡터 색인
  (64,239건 8분 33초, alias 무중단 스왑·증분·멱등 point id), `/v1/vsearch` 신설(엔진 내 필터·반경).
  **실측이 세 가지를 뒤집었다:** ① 벡터가 키워드보다 느리지 않다(4.8ms vs 8.0ms) ② 감으로 잡은
  문턱 0.78은 아무것도 못 거른다(→ 분포 재고 0.84) ③ 벡터는 `회 먹을 데`처럼 키워드가 0건인
  질의를 살리지만, 원천에 없는 `스타벅스`에도 답을 지어낸다. 크리틱 #15~#17 신규.
- ✅ 6단계 완료 (2026-07-23): 앱단 RRF 결합(`/v1/hsearch`) — 두 채널 코루틴 팬아웃 → 등수 결합
  → 페이지 슬라이스. 실제로 칠 법한 질의 20개에서 **0건이 10 → 1**. 지연 16.3ms(키워드 단독 9.2ms)
  이고 결합 계산 자체는 0.21ms — 비용은 전부 '두 번 부르기'와 '깊게 뜨기'에서 나온다.
  한 채널이 죽어도 반쪽으로 답하는 것(`degraded`)을 컨테이너 중단으로 양방향 실측. RRF 는 순수
  함수로 분리해 11개 테스트로 성질을 고정(총 45개 통과). **반경 필터를 걸면 벡터가 0건이 되던
  버그를 발견·수정** — 절대 문턱을 필터 없는 코퍼스에서 정해 놓고 필터된 집합에 그대로 댄 탓
  (ADR 0010 후속). 크리틱 #17 은 recall 만 해결되고 precision 은 미해결로 남음, #18·#19 신규.
- ✅ 2단계 재방문 (2026-07-23): 6단계 데모에서 `스타벅스` 0건을 확인하고 원인을 파다가,
  **원천이 스타벅스를 브랜드명 없이 등록**해 뒀음을 발견(`스타벅스 신사역점` → `신사역`).
  두 번째 원천(행안부 인허가, 강남구 휴게음식점 3,934건)과 행정동 경계(전국 3,558개)를 적재하고,
  좌표계(EPSG:5174)를 5181과 전수 대조해 확정. 공간 조인으로 인허가에 행정동을 부여하고
  **원천의 행정동을 처음 검증**(64,239건 중 99.70% 일치, 경계 밖 0). 브랜드 86건 복원 →
  `스타벅스` 검색 0건 → **86건**, 자동완성도 `스타벅` → 스타벅스 매장. 벡터도 재임베딩(511초,
  95.6%가 추론)해 0 → 26건, **하이브리드 상위 10건이 전부 두 채널 합의**로 바뀜. 크리틱 #20 신규.
- ✅ 모듈 분리 (2026-07-24): 한 아티팩트를 **`search-core` / `search-api` / `indexer-batch`** 로 쪼개고
  `psp.role.*` 런타임 플래그를 **전부 제거**했다 — 모듈이 곧 역할. 검증은 말이 아니라 jar 로 했다
  (`search-api.jar` 안에 r2dbc/postgresql **0개**, `Admin` 클래스 **0개**). 쪼개면서 ADR 0010 이
  코드로 강제하던 보호(색인·질의가 같은 모델)를 잃으므로 **런타임 버전 도장**(`IndexMeta`)을 함께
  넣었다 — `SCHEMA_VERSION` 을 일부러 틀리게 하고 질의기가 **기동에 실패**하는 것까지 확인.
  증분 색인이 모델이 바뀐 채 돌아 인덱스를 섞는 것도 **사전 차단**한다. 실측 재검증: 키워드 재색인
  17초·벡터 8분 12초(임베딩 95.7%)로 분리 전과 동일, 질의 20개 회귀에서 0건 수가 **완전히 동일**
  (키워드 7·벡터 2·하이브리드 0), 하이브리드 중앙값 8.2ms. → ADR 0011, 크리틱 #5·#14·#15 갱신
- 🐛 그 과정에서 **분리와 무관한 버그**를 잡았다 (2026-07-24): Jackson 2/3 가 공존하는데 Kotlin
  모듈이 Jackson 3 에만 붙어 있어, ES `_source` 가 **전부 기본값**으로 역직렬화되고 있었다.
  `/v1/search` 가 187건을 200 OK 로 돌려주면서 이름이 전부 빈 문자열이었다. 체크포인트도 못 읽어
  증분 색인이 매번 폴백했고, 하이브리드는 사실상 벡터 단독으로 돌고 있었다. `main` 에서도 재현돼
  **초기 스냅샷부터 있던 버그**로 확인. 회귀 측정을 스크립트로 고정했다
  (`scripts/measure_search.py`). → 크리틱 #26
