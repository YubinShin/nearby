# 로드맵 — 무엇을, 어떤 순서로

이 프로젝트의 목표는 **로컬(docker compose)에서 검색 파이프라인이 실제로 끝까지 도는 것**이에요.
데이터 적재 → 색인 → 키워드+벡터 검색 → RRF 결합 → 거리 다듬기까지 *진짜로 동작*하는 걸 목표로 해요.

무엇을 **실제로 만들고**, 무엇을 **설계 문서로만 남기는지**를 분명히 나눠요. 다 만드는 게 목표가
아니라, "이런 걸 설계할 줄 안다"를 **동작하는 핵심 + 확장 설계**로 보여주는 게 목표예요.

## 원칙

- **핵심은 동작, 확장은 설계.** 검색의 뼈대(색인·키워드·벡터·결합)는 실제로 돌리고, 운영 고도화
  (K8s 무중단 배포·멀티클러스터·Kafka 색인·추천 고도화)는 근거 있는 설계 문서로 남겨요.
- **결정마다 ADR.** 왜 그렇게 했는지를 [ADR](adr/)에 남겨요. 이게 이 프로젝트의 알맹이예요.
- **매 단계 빌드/기동 검증.** 문서만 있고 안 도는 상태를 만들지 않아요.

## 설계 문서로만 남기는 범위 (이번엔 구현하지 않음)

실무 경험이 있는 영역이지만, 로컬 데모 범위를 넘어서므로 **구조와 근거만** 남겨요.

- **K8s 무중단 배포** — alias 스왑 기반 인덱스 교체를 K8s에서 운영하는 방식
- **멀티클러스터** — 용도별 클러스터 분리·확장 토폴로지 (ADR 0002의 연장)
- **Kafka 스트리밍 색인** — 증분 색인을 이벤트 스트림으로 (ADR 0001의 연장)
- **추천 고도화** — Item2Item·Sequence·Discovery, Circuit Breaker/Fallback 체인
