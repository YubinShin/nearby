# 로드맵 — 무엇을, 어떤 순서로

이 프로젝트의 목표는 **로컬(docker compose)에서 검색 파이프라인이 실제로 끝까지 도는 것**입니다
— 데이터 적재 → 색인 → 키워드+벡터 검색 → RRF 결합 → 거리 다듬기. 무엇을 실제로 만들고
무엇을 설계 문서로만 남기는지를 분명히 나눕니다.

## 원칙

- **핵심은 동작, 확장은 설계.** 검색의 뼈대(색인·키워드·벡터·결합)는 실제로 돌리고, 운영 고도화
  (K8s 무중단 배포·멀티클러스터·Kafka 색인·추천 고도화)는 근거 있는 설계 문서로 남깁니다.
- **결정마다 ADR.** 왜 그렇게 했는지를 [ADR](adr/)에 남깁니다. 이것이 이 프로젝트의 핵심입니다.
- **매 단계 빌드/기동 검증.** 문서만 있고 돌지 않는 상태를 만들지 않습니다.

## 설계 문서로만 남기는 범위 (이번엔 구현하지 않음)

실무 경험이 있는 영역이지만, 로컬 데모 범위를 넘어서므로 **구조와 근거만** 남깁니다.

- **멀티클러스터** — 용도별 클러스터 분리·확장 토폴로지 (ADR 0002의 연장)
- **Kafka 스트리밍 색인** — 증분 색인을 이벤트 스트림으로 (ADR 0001의 연장).
  들어올 자리를 `services/indexer-stream/` 에 **빈 모듈로 만들어 뒀습니다** — 이름을 고른 근거와
  채워질 조건은 그 모듈 README 에 있습니다 (ADR 0011).
- **추천 고도화** — Item2Item·Sequence·Discovery, Circuit Breaker/Fallback 체인
